# 技術方針・安全ルール・UI方針

このプロジェクト全体で常に守るルール。

## 技術方針
- Electron(メインプロセス + プリロード + レンダラー)。HTTPサーバーは持たない
- レンダラーからメインプロセスへは、`contextBridge` で公開した `window.launcherAPI` 経由のIPCのみでやり取りする(`nodeIntegration: false` / `contextIsolation: true` を維持する)
- データはローカルの `data/work-modes.json` と `data/settings.json` のみに保存する。クラウド・外部DBは使わない
- 対象環境はWindows 10/11。macOS・スマートフォン対応は行わない
- タスクトレイに常駐し、ウィンドウを閉じてもプロセスは終了しない(トレイメニューの「終了」でのみ終了する)

## 安全ルール(最重要)
- ユーザーが入力した文字列を、そのままシェル(PowerShell・コマンドプロンプト)へ渡さない
- URL・ファイル・フォルダを開く処理は、`shell.openExternal` / `shell.openPath` (Electron標準API)のみを使う。`child_process` でシェル経由の起動コマンドを組み立てない
- 自由なコマンド実行機能を作らない。実行できる操作は「登録済みのURL・ファイル・フォルダを開く」ことに限定する
- URLは `http://` または `https://` のみ許可する
- ファイル・フォルダは「開く」以外の操作(作成・更新・移動・削除)を行わない
- パスは登録時と実行直前の両方で実在確認を行う。存在しない対象は開かず、対象ごとに失敗理由を表示する
- 一括起動の前に、開く対象の一覧を必ずプレビュー表示し、利用者の確認を挟む(「起動前の確認をスキップする」設定は利用者自身が明示的に選んだ場合のみの例外とする)
- 認証情報・Cookie・パスワード・ファイル内容は保存も送信もしない
- グローバルホットキーは「ウィンドウの表示/非表示を切り替える」以外の操作を割り当てない
- `dialog.showSaveDialog` / `dialog.showOpenDialog` は業務モードのバックアップ書き出し/読み込み専用とし、任意のファイル読み書きに使わない
- 自動起動はElectron標準の `app.setLoginItemSettings` のみを使う。スタートアップフォルダやレジストリを直接操作しない
- 通知(`Notification`)には実行結果の件数・成否のみを含め、登録内容の詳細(URL・パス本文)は含めない

## UI方針
- 画面表示・エラーメッセージはすべて日本語にする
- 失敗時は「ファイルが見つかりません」のように、利用者が対処できる具体的な表現にする
- 削除など取り消しにくい操作の前には確認を挟む
- ウィンドウは小型・フレームレスの常駐ウィジェットとして扱う。トレイアイコンから開閉できることを前提にUIを組む
